# Runtime static hosting

Build with `pnpm --filter @flanksource/page-runtime build`. The worker compiles live pages with the base MDX plugins only. `export-compiler.js` is loaded only for an HTML or PDF export and runs the plugins libraries declare (see `src/build/README.md`). Add `--dev` to bundle every `@flanksource/*` dependency from a sibling checkout of this workspace instead of its installed release; the build logs which checkout each package came from. An import that resolves nowhere fails the build.

Serve `dist/static/` over HTTPS (localhost works for development). Serve `bootstrap.html` for `/frame/*` on the first visit, and make `/sw.js`, `/boot.js`, `/page-agent.js`, `/export-compiler.js`, `/devtools-hook.js` and `/profile.json` available from the origin root. Use a separate runtime origin from the host. The first visit registers the worker and reloads once. `profile.json` is required and validated; configure it for the deployment using the example below. Profile changes require a worker upgrade/reload.

Frames get a strict Content Security Policy: `script-src 'self'` plus a per-document nonce, with no `eval` and no WebAssembly. `csp.add` appends sources to any directive. To let page code compile WebAssembly, opt in with `"csp": { "add": {}, "wasm": true }`, which adds `'wasm-unsafe-eval'` to `script-src`. It allows WebAssembly compilation only, not JS `eval`, and it is off when omitted. The runtime itself never needs it: the worker is not governed by the frame policy, and the export compiler uses an asm.js lexer.

The host embeds `PageFrame` from `@flanksource/page-runtime/host`, passing `runtimeOrigin`, `open: { page, manifest, files, lock? }`, `theme`, `data` and `onError`. The host can retain the bridge with `onBridge`; send `sources` to update buffers and reload, or request `{ type: "export", format: "html" }` / `{ type: "export", format: "print" }`. The frame's `connecting` status requests initial configuration, `booting` requests data and theme, and `ready` permits exports. Sessions are fresh for each embedding.

For local development only, `origin="same-origin-local"` explicitly permits `runtimeOrigin={location.origin}` on localhost, 127.0.0.1 or ::1. Both frame and host enforce the opt-in; the default remains cross-origin-only. Exact origin, source-window and session validation is unchanged. The worker registers with scope `/frame/`: it controls runtime frame documents and handles their `/src/`, `/npm/`, `/link/` and `/__runtime/` fetches, while the host document and its own requests stay outside its scope. Reserve `/frame/` for runtime documents. This local mode shares the host realm's origin authority and is not a production isolation boundary; P7 remains deferred.

`PageLock` is serializable. The frame emits a validated `lock` message; a source provider should persist it beside writable sources, hash-page URLs or browser state, and supply it in `open.lock`. Supplying a lock bypasses registry resolution. The worker persists opened pages in versioned Cache Storage and reuses their locks while the folder manifest is unchanged. The package origin uses the unpkg layout (`/<name>@<exact-version>/<file>`), including `?meta` file listings for additional ESM packages. Libraries publish `runtime/importmap.json` and `runtime/barrels.json`; named imports are pruned only where the package's `sideEffects` declaration permits skipping the barrel.

P3 can install `window.__PAGE_RUNTIME_STYLES__ = { prepare }` before page boot. `prepare({ config, candidates })` is awaited before React mounts. The worker extracts candidates from every page module and exposes `/__runtime/candidates?page=<page>`. P5 can extend the validated bridge catalog for agent messages; P6 owns linked-library routing. CSP additions and network patterns are explicit profile seams; P7 hardening remains separate.
